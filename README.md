# koala (koa)

브라우저 확장 사이드패널에서 자연어로 지시하면, 내 PC의 Claude Code가 브라우저를 직접 조작하며 웹 서비스를 QA합니다.
확인한 내용은 BDD 시나리오·TDD 케이스로 정리하고, Playwright 테스트 코드로 만들어 CI에서 반복 실행합니다.

- **등록**: AI와 사람이 화면에서 확인하며 테스트를 만든다
- **동작**: 만들어진 Playwright 코드대로 반복 실행한다

> 시험판(`spike/`) 단계입니다. 확장은 Chrome 개발자 모드로 설치합니다.

## 주요 기능

- **세트**: 대상 서비스·버전·목적 단위(예: `서비스A 2.0 취약점 점검`)로 테스트·기록·세션을 따로 관리합니다. 세트 정의는 서버에서 받습니다.
- **대화로 테스트**: "로그인하고 회원가입 화면 입력란 확인해줘"처럼 지시하면 AI가 작업 탭을 조작하고, 단계·요청·콘솔 오류를 타임라인에 보여 줍니다.
- **작업 탭**: AI는 정해 둔 탭(관리 탭 **#1, #2 …**)에서만 조작하므로 그동안 다른 탭을 써도 됩니다. "#2 탭에서 …"처럼 탭을 골라 지시합니다.
- **테스트 만들기**: 수행 이력으로 BDD 시나리오와 TDD 케이스 초안을 만들고, 채택·미채택을 골라 반영합니다. 미채택 항목은 지우지 않고 남겨 두었다가 다시 살릴 수 있습니다.
- **예외·오류 점검**: 필수값·형식·중복 제출·세션 만료·권한·서버 오류·지연·네트워크 끊김·탭 순서를 점검표로 채우고, 오류 주입으로 직접 수행합니다.
- **코드 생성과 로컬 실행**: 채택한 항목으로 Playwright 코드를 만들고 바로 실행해 결과를 확인한 뒤 서버로 보냅니다.
- **역할**: 관리자·일반 사용자 같은 역할을 골라 여러 역할로 한 번에 수행하고, 역할마다 메뉴 권한 차이를 찾아 표로 정리합니다.
- **태그**: 서버가 주는 태그 목록(실행 범위·기능 영역·우선순위 등)을 시나리오와 케이스에 붙여 CI에서 골라 돌립니다.
- **Claude 연결과 사용량**: 사이드패널을 열면 Claude를 미리 연결합니다. 모델·effort를 고르고, 구독 한도(5시간·주간)의 사용량과 남은 양을 봅니다. 구독 대신 **API 키(Console 크레딧)**로 돌릴 수도 있습니다.
- **피드백**: 메뉴(⋯) → **피드백 보내기**로 버그·제안·질문을 koala GitHub Issues에 올립니다.

## 구성

```
Chrome 확장(사이드패널) ⇄ 로컬 호스트(node, 127.0.0.1:8765) ⇄ Claude Code(내 PC, 내 계정)
                              ├─ 동기화 저장소(store/: 공용 예시, .koa/store/: 이 PC의 문서)
                              ├─ 작업 폴더(.koa/sets/<세트 id>/work/claude: Claude가 읽는 지식 사본)
                              └─ 경로 그래프(PostgreSQL + Apache AGE, 선택)
```

| 폴더·파일 | 역할 |
|---|---|
| `spike/extension/` | Chrome 확장(사이드패널, 화면 조작, 네트워크·콘솔 수집) |
| `spike/host.mjs` | 확장과 Claude Code를 잇는 로컬 호스트 |
| `spike/mcp-server.mjs` | Claude가 쓰는 브라우저 도구(click, type, expect_* 등) |
| `spike/store/` | 동기화 저장소의 공용 예시(나중에 백엔드로 바뀜): 공통 지식, 태그, 예시 프로필·역할 |
| `spike/.koa/store/` | 이 PC의 동기화 문서(서버 흉내): 세트 정의, 대상 서비스 프로필·지식(git 제외) |
| `spike/.koa/sets/` | 세트별 작업 데이터: 받은 정의, 테스트, 수행 기록, 로그(git 제외) |
| `spike/generate.mjs` | 수행 기록 → Playwright 코드 |
| `spike/tests/` | 생성된 테스트와 정리 도구(git 제외) |
| `docs/` | 목표·결정 기록, 벤치마킹, Windows 설치 가이드 |

## 준비물

| 항목 | 필수 | 비고 |
|---|---|---|
| Chrome (또는 Edge, Brave) | 필수 | 확장을 개발자 모드로 설치 |
| Node.js 20 이상 | 필수 | |
| Git | 필수 | 설치·업데이트가 릴리즈 태그를 받습니다 |
| Claude Code | 필수 | **각자 설치하고 각자 계정으로 로그인**합니다. 사용량도 각자 계정에서 나갑니다. API 요금제로 쓰면 로그인 대신 Console API 키가 필요합니다 |
| 대상 서비스 접근 | 필수 | 테스트할 웹 서비스에 이 PC의 브라우저로 접속할 수 있어야 합니다 |
| Docker | 선택 | 경로 그래프(지나간 경로를 기억해 빠르게 재생). 없으면 재생 없이 동작 |

## 설치

### macOS·Linux: 한 줄 설치

```bash
curl -fsSL https://raw.githubusercontent.com/xivicWon/koala/main/install.sh | sh
```

- 최신 GitHub 릴리즈(태그)를 `~/koala`에 받아 의존성을 설치하고 `.env`를 만듭니다.
- 사이드패널을 열면 호스트가 자동으로 켜지도록 등록합니다(Chrome·Edge·Brave Native Messaging). 터미널을 열어 둘 필요가 없습니다.
- 옵션: `KOALA_HOME=다른/위치`, `KOALA_TAG=v0.5.2`(특정 버전), `KOALA_GRAPH=1`(경로 그래프 DB도 Docker로 켬)
- 최신 버전은 GitHub API가 아니라 릴리즈 페이지 주소로 찾으므로, 같은 네트워크에서 여러 번 설치해도 호출 한도에 걸리지 않습니다.

### Windows

[Windows 설치 가이드](docs/install-windows.md)를 따릅니다. 한 줄 설치 스크립트는 아직 없습니다.

### 설치한 뒤 처음 한 번

1. `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기 → **압축해제된 확장 프로그램 로드** → `~/koala/spike/extension`
2. 툴바의 퍼즐 아이콘 → koala 고정 → 아이콘을 누르면 사이드패널이 열립니다.
3. Claude Code에 로그인되어 있지 않으면 터미널에서 `claude auth login`
4. 사이드패널 상단의 **세트 칩**에서 점검할 세트를 고르고, **역할과 계정**에 역할별 테스트 계정을 입력합니다. 계정 값은 내 확장에만 저장되고 공유되지 않습니다.
   - 처음에는 예시 세트만 있습니다. 서버 세트는 세트 시트에서 **받기**로 받고, 서버에 없는 사이트는 **이 PC 전용 세트**로 만듭니다.

### 직접 설치 (개발용)

```bash
git clone https://github.com/xivicWon/koala.git && cd koala/spike
npm install
cp .env.example .env
npm start            # 호스트. 쓰는 동안 터미널을 열어 둡니다
```

- 확장은 위와 같이 `koala/spike/extension`에서 불러옵니다.
- (선택) 경로 그래프 DB: `npm run graph:up`
- 개발 체크아웃(태그가 아닌 브랜치)은 자동 업데이트 대상이 아닙니다.
- 설치본과 개발 폴더를 함께 두면 둘 다 포트 8765를 씁니다. 먼저 켜진 호스트에 확장이 붙으므로, 다른 폴더의 호스트면 이름 옆에 **호스트 불일치**가 뜹니다.

## 사용

테스트 목록 위쪽의 **단계 안내**(① 수행 → ② 테스트 만들기 → ③ 고르고 반영 → ④ 코드 생성·실행 → ⑤ 서버 전송)가 지금 단계와 누를 버튼을 알려 줍니다. 입력창 위 **사용 가이드**에는 말하는 예시가 있습니다.

1. **대화로 테스트**: 대상 사이트를 탭에 열고 사이드패널을 엽니다. 세트가 골라져 있으면 그 탭이 **작업 탭(#1)**이 됩니다(세트 사이트가 아닌 탭이면 안내만 하고, 위쪽 **지금 탭으로**로 정합니다). 확인할 흐름을 적어 **Enter**로 실행합니다(줄바꿈은 **Shift+Enter**, AI 작업 중에는 Enter로 멈추지 않으니 멈출 때는 **중지** 버튼).
   - 단계 카드, 문제가 있는 요청(오류·느림), 콘솔 오류가 타임라인에 나옵니다. **요청** 버튼으로 헤더·본문·쿠키를 보고 YAML/JSON으로 복사합니다.
   - 처음 가는 경로는 **탐색**(x1), 지나간 경로는 **재생**(x2)으로 진행합니다. 위쪽 **▾ x1 ▴**(배속)와 **❚❚**(일시정지)는 AI가 작업 탭을 조작하는 동안에만 켜지고, 바꾸면 다음 단계부터 적용됩니다. 배속은 화면에서 조작을 보여 주는 속도일 뿐이라 테스트 결과·생성 코드·Playwright 실행 속도와는 관계없습니다.
   - 역할이 여럿이면 입력창 아래 **역할 칩**으로 수행할 역할을 고릅니다. 여럿을 고르면 차례로 다시 로그인해 수행하고, 끝에 역할 × 항목 권한 표를 보여 줍니다.
2. **테스트 생성**: 수행이 끝나면 입력창에 "지금까지 한 걸로 테스트 만들어줘"라고 합니다. 그 응답이 끝난 뒤 BDD 시나리오·TDD 케이스·예외 점검표 초안이 만들어집니다. "로그인 부분만"처럼 범위를 붙일 수 있습니다.
   - 점검표에 미수행 항목이 있으면 **예외·오류 보강 수행**으로 AI가 직접 수행해 채웁니다.
3. **채택·반영**: **테스트 목록**의 BDD·TDD 탭에서 항목을 채택하거나 미채택하고, 탭 맨 위의 **반영**을 누릅니다(반영하면 테스트 코드 탭으로 넘어갑니다). 아예 뺄 항목은 카드의 휴지통을 두 번 눌러 지웁니다(BDD는 딸린 TDD 포함, 지우기 전 목록은 세트 폴더에 보관). 새로 생긴 항목에는 **New** 표시가 붙습니다. **태그 붙이기**로 서버 태그를 고르게 합니다.
4. **코드 생성·로컬 실행**: **코드 생성**으로 Playwright 코드를 만들고 이 PC에서 바로 실행해 결과(통과·실패·보류)를 봅니다.
5. **서버 전송**: 결과를 확인한 뒤 **서버 전송**으로 세트의 테스트를 세트의 **배포 서버**로 보냅니다. 배포 서버가 없으면 이 버튼은 꺼져 있습니다. 보내는 형태는 아직 임시(JSON)라 공사 중 표지판을 확인한 뒤 보냅니다.

- 빠진 시나리오가 있으면 테스트 목록의 **+ 테스트 추가**에 적습니다. 기존 항목은 그대로 두고 새 항목과 코드만 더합니다.
- 다시 시작하려면 테스트 목록의 **초기화**(BDD·TDD·흐름·예외 점검표·코드·실행 결과 전부), 일부만 지우려면 각 탭의 **모두 지우기**(BDD는 딸린 TDD까지)를 누릅니다. 지우기 전 목록은 세트 폴더 `tests/archive/`에 남고, 서버에 이미 보낸 것은 지우지 않습니다.
- 데이터를 만드는 테스트는 이름 앞에 `[koa]`가 붙고, 프로필의 정리 규칙(`cleanup`)대로 끝나면 정리합니다.

## Claude 연결과 사용량

- 사이드패널을 열면 호스트가 Claude를 미리 띄우고, 세션이 없으면 새로 엽니다(`kaa-N`). 연결하는 동안 Claude 버튼의 점이 노랗게 깜박입니다. 갑자기 끊기면 같은 세션으로 다시 연결합니다.
- **Claude** 버튼을 누르면 설정 창이 열립니다.
  - **모델·effort 고르기**: 모델(Opus·Sonnet·Haiku·Fable 또는 기본)과 effort(low~max)를 고릅니다. 이 확장에 내 설정으로 저장되어 세트 설정보다 우선하고, 바꾸면 대화는 그대로 이어서 새 설정으로 다시 연결합니다. AI 작업 중에는 바꿀 수 없습니다.
  - **요금제**: *Claude Code 구독*(기본, 이 PC에 로그인한 구독 한도) 또는 *API 키 (크레딧)*. API 키를 고르면 [Anthropic Console](https://console.anthropic.com) › API Keys에서 만든 키를 넣고 **저장**합니다. 키는 호스트가 이 PC의 `~/.koala/anthropic-api-key`(본인만 읽기)에만 저장하고, 패널·작업 기록·서버로는 보내지 않습니다. API 요금제는 Claude Code를 라이브러리로 쓰는 **Agent SDK**로 실행되어, API 크레딧(프로모션 크레딧 포함)에서 차감됩니다. 바꾸면 대화는 이어서 다시 연결합니다.
  - 지금 쓰는 모델·effort·세션, 그리고 **구독 한도 사용량**(5시간·주간): 사용률, 남은 양, 초기화 시각. API 요금제에서는 대신 **이 대화와 마지막 지시의 비용**(정가 기준 추정)을 보여 줍니다. 실제 차감액은 Console의 Usage·Billing에서 확인하세요.
  - 이 세션에서 쓴 응답 수와 입력·출력 토큰
  - **압축**(대화를 요약해 토큰 절약), **세션 비우기**(대화만 새로), **기록까지 비우기**(수행 기록까지 처음부터)
  - **자세히**: 작업 폴더, 실행 옵션, AI에게 실제로 전달되는 내용
- 모델·effort는 **내 설정 → 세트의 `claude.model`·`claude.effort` → Claude Code 기본값** 순으로 정합니다.

## 피드백

- 메뉴(⋯) → **피드백 보내기**에서 종류(버그·개선 제안·질문), 제목, 내용을 적고 **GitHub 이슈로 열기**를 누르면, koala 공개 저장소(`xivicWon/koala`)의 새 이슈 화면이 내용이 채워진 채로 열립니다. 확인한 뒤 GitHub에서 **Submit new issue**를 눌러 올립니다(GitHub 로그인 필요).
- 공개 저장소라 자동으로 붙이는 정보는 koala 버전·브라우저·OS뿐입니다. 대상 사이트 이름·주소·계정·화면 내용은 적지 마세요. **내용 복사**로 다른 곳에 붙여 넣을 수도 있습니다.

## 세트·역할·지식 문서

| 문서 | 내용 |
|---|---|
| 프로필 `profiles/<id>.yaml` | 대상 주소, 시작 URL, 배포 서버, 연결된 지식·태그·역할 문서, 사이트 운영 팁(prompt), 정리 규칙 |
| 역할 문서 `roles/<id>.yaml` | 역할(관리자·일반 사용자 등)과 기본 역할. 역할별 기본 계정 값은 git 밖 `spike/.koa/server-accounts/<id>.yaml` |
| 지식 문서 `knowledges/<id>.yaml` | 공통 QA 원칙, 서비스 목적·주요 기능·중점 QA 방향 |
| 태그 문서 `tags/<id>.yaml` | 테스트에 붙일 태그 목록과 붙이는 기준 |

- 문서는 `spike/.koa/store/`(이 PC, git 제외)를 먼저 보고, 없으면 `spike/store/`(공용 예시)를 씁니다. 서버로 보낸 테스트도 `.koa/store/`에 저장됩니다. 대상 서비스 정보가 공개 저장소에 들어가지 않게 하기 위해서입니다.
- 메뉴 권한은 서비스마다 방식이 달라 문서에 적지 않습니다. AI가 역할마다 직접 찾습니다.
- **배포 서버**(`deploy.url`): 서버 전송이 테스트 묶음을 보내는 곳입니다. 동기화 저장소와 같은 모양의 API(`PUT <서버>/sync/suites/<id>`, 충돌이면 409)를 씁니다. 이 PC의 임시 서버를 쓰려면 `http://127.0.0.1:8765`를 넣습니다.
- **세트는 서버가 내려주고 사용자는 받아서 씁니다.** 세트는 대상 서비스·버전에 목적을 붙인 점검 단위(예: `서비스A 2.0 취약점 점검`)이고, 대상 사이트는 세트당 하나입니다. 받은 정의(프로필·역할·지식·태그)는 패널에서 읽기 전용이고, 사람마다 다른 **시작 URL**·**내 계정**·**역할 범위**만 세트마다 '내 설정'으로 이 확장에 저장합니다.
- 서버에서 세트 정의가 바뀌어도 자동으로 덮어쓰지 않습니다. 세트 칩에 점과 바뀐 것이 보이면 **받기**를 직접 누릅니다. AI 작업·테스트 실행 중에는 받기와 세트 전환이 거절됩니다. 지금은 공유 서버가 없어 이 PC의 임시 저장소(`spike/.koa/store/sets/`)의 파일을 고칩니다.
- 서버에 없는 사이트를 시험하려면 세트 시트에서 **이 PC 전용 세트**를 만듭니다. 직접 고치고 지울 수 있고, 다른 PC로는 가지 않습니다.
- **시작 URL**(`target.start_url`): 새 수행 기록은 이 주소에서 출발하고, 생성 코드도 여기서 시작합니다. 대상 주소와 같은 도메인만 씁니다. 비우면 지금 탭 주소에서 시작합니다.

## 데이터는 어디에 남나

작업 데이터는 **세트별로** 한 폴더(`spike/.koa/sets/<세트 id>/`)에 모입니다. 같은 사이트의 세트끼리도 섞이지 않고, 세트를 지우거나 옮기는 일은 폴더 하나로 끝납니다. 도메인은 저장 위치에 쓰지 않고, 대상 탭이 세트의 사이트와 맞는지 확인하는 데만 씁니다. 탭이 다르면 멈추고 묻습니다: **세트 주소로 이동**하거나 **그래도 진행**을 고릅니다. 테스트 실행도 지금 탭이 다른 도메인이면 한 번 확인합니다(테스트는 탭이 아니라 세트의 대상 주소로 새 창에서 돕니다).

**작업 탭**: AI는 화면에 보이는 탭이 아니라 세트마다 정한 작업 탭에서만 조작합니다. 처음 지시할 때 보던 탭이 작업 탭이 되고, 노란 탭 그룹(`koala · 세트 이름`)으로 묶여 koala가 관리하는 탭임을 알 수 있습니다. 작업 중에 다른 탭을 봐도 AI는 작업 탭에서 계속합니다(뒤에 있어도 화면이 그려지도록 포커스를 흉내 냅니다). 작업 탭에서 링크로 열린 새 탭은 같은 그룹에 들어가고 그 탭으로 이어 가며, 닫히면 작업 탭으로 돌아옵니다. 탭을 노란 그룹으로 끌어 넣으면 koala가 관리하는 탭이 됩니다(작업 탭이 없으면 바로 작업 탭). 패널 위쪽 **탭 N**을 누르면 그룹 안 탭 목록이 열리고, 거기서 **작업 탭으로**·**보기**를 고릅니다. **지금 탭으로**는 보고 있는 탭을 그룹에 넣고 작업 탭으로 바꿉니다. AI는 한 번에 작업 탭 하나에서 조작합니다. 작업 탭을 닫으면 진행을 멈추고, 그룹 밖으로 빼면 그룹의 다른 탭으로 옮깁니다.

관리 탭에는 **#1, #2 …** 번호가 붙습니다(빈 번호부터, 그룹에서 빠지면 번호를 돌려줌). 번호는 사이드패널(위쪽 작업 탭 표시와 **탭 N** 목록)에서만 보이고, 브라우저 탭 줄에는 세트 그룹 하나만 보입니다. "#2 탭에서 …"처럼 지시하면 AI가 `use_tab`으로 그 탭으로 바꿔 진행하고, 관리 탭이 둘 이상이면 지시에 탭 목록이 함께 전달됩니다. AI의 모든 조작 결과와 수행 기록·작업 로그에는 어느 탭(#번호)에서 했는지가 남습니다.

| 데이터 | 위치 | git |
|---|---|---|
| 세트별 내 설정(시작 URL, 내 계정, 역할 범위), 화면 설정, 타임라인 | Chrome 확장 저장소(확장을 지우면 함께 삭제) | - |
| 서버 흉내(세트 정의, 프로필·지식·태그 문서) | `spike/.koa/store/` | 제외 |
| 받은 세트 정의(읽기 전용 스냅숏) | `spike/.koa/sets/<세트 id>/set.json`, `received/` | 제외 |
| 서버가 준 기본 계정 | `spike/.koa/sets/<세트 id>/secrets/` (권한 0600) | 제외 |
| 테스트 목록(호스트에 저장), 테스트 코드, 실행 결과 | `spike/.koa/sets/<세트 id>/tests/` (`tests.json`, `code/*.spec.ts`, `results/`) | 제외 |
| 수행 기록·보관본, Claude 세션, Claude 작업 폴더 | `spike/.koa/sets/<세트 id>/work/` (`state.json`, `recordings/`, `claude/`) | 제외 |
| 작업 로그(지시·도구 호출·테스트 실행·안내 문구) | `spike/.koa/sets/<세트 id>/work/logs/<날짜>.jsonl` — 메뉴(⋯) → **작업 로그 폴더 열기**. 30일 지나면 지움. 비밀값은 `$KOALA_*` 이름만 남음 | 제외 |
| 마지막 전송 기록(버전·시각) | `spike/.koa/sets/<세트 id>/outbox/` | 제외 |
| 예전 방식 데이터 보관본 | `spike/.koa/migrated-<날짜>/` | 제외 |
| 역할별 기본 계정(서버 흉내) | `spike/.koa/server-accounts/` | 제외 |
| 기본 계정(예전 방식), Claude 위치 | `spike/.env` | 제외 |
| 호스트 기록 | `~/.koala/host.log` | - |
| AI 대화 기록 | `~/.claude/projects/…` | - |
| 경로 그래프 | Docker 볼륨 `koala-graph` | - |

- 업데이트한 뒤 처음 연결하면 예전 프로필·도메인별 데이터를 세트로 옮깁니다. 원본은 `.koa/migrated-<날짜>/`에 보관되고, 옮긴 뒤 첫 대화는 새 세션으로 시작합니다.
- 서버 전송은 **임시 형태**입니다(공사 중). 서버로 보내는 데이터의 형태가 정해지면 바뀌며, 지금은 채택·미채택 모두 adopted 표시와 함께 JSON으로 보냅니다. 앱에서 쓰려 하면 공사 중 표지판이 지금 되는 것과 안 되는 것을 알립니다.

## 보안

- 호스트는 `127.0.0.1`에서만 열리고, koala 확장 출처(Origin)와 이 PC의 koala 프로세스(`spike/.koa/host-token`)의 요청만 받습니다. 다른 웹 페이지는 호스트에 접속할 수 없습니다.
- AI와 생성 코드에는 `$KOALA_ADMIN_PASS` 같은 **이름만** 전달되고, 실제 값은 호스트가 채웁니다. AI가 계정 값을 입력하는 것은 세트의 대상 서버 화면(작업 탭)에서만 허용됩니다.
- 계정 비밀번호는 지금 **평문**으로 확장 저장소와 `.env`, `.koa/server-accounts/`에 있습니다(OS 키체인 적용은 보류).
- 요청 상세의 비밀번호·토큰은 가려지지만 **세션 쿠키는 그대로 보입니다.** 복사한 내용을 공유할 때 주의하세요.

## 문제 해결

| 증상 | 해결 |
|---|---|
| "호스트가 실행 중이 아닙니다" | 설치본: 설치 스크립트를 다시 실행해 자동 실행을 다시 등록. 개발용: `spike`에서 `npm start` |
| "호스트를 켜지 못했습니다" | `~/.koala/host.log` 확인 |
| 이름 옆에 "호스트 불일치" | 확장과 다른 폴더의 호스트가 켜져 있습니다. 그 호스트를 끄면 사이드패널이 맞는 호스트를 켭니다 |
| "Claude Code를 찾을 수 없습니다" | Claude Code 설치. 다른 위치면 `.env`에 `CLAUDE_BIN` 지정 |
| "로그인되어 있지 않습니다" | `claude auth login` (또는 Claude 설정에서 요금제를 API 키로) |
| "API 요금제에 쓸 키가 없습니다" / "Invalid API key" | Claude 설정 › 요금제에서 Console API 키를 다시 저장 |
| "Credit balance is too low" | Console › Billing에서 크레딧 잔액 확인 |
| Claude 점이 빨강 | 툴팁에 원인이 나옵니다. 연결이 끊기면 자동으로 다시 연결하고, 세 번 실패하면 다음 지시 때 다시 시도합니다 |
| 조작이 "요소 없음"으로 실패 | 위쪽 **작업 탭 #N**이 대상 사이트 화면인지 확인. 다른 탭이면 그 탭에서 **지금 탭으로**, 또는 **탭 N** 목록에서 고르기 |
| 설치가 "최신 릴리즈를 알아내지 못했습니다"로 멈춤 | 버전을 지정해 다시 실행: `curl … install.sh \| KOALA_TAG=v0.5.2 sh` |
| "대상 탭이 … 입니다"로 실행 안 됨 | 작업 탭이 세트의 사이트가 아닙니다. 메시지의 이동·그래도 진행을 누르거나, 위쪽 **지금 탭으로**로 작업 탭을 바꿉니다 |
| 계정 입력이 거부됨 | 계정 값은 세트의 대상 서버 주소 화면에서만 입력됩니다. 세트 상세의 대상 주소 확인 |
| 생성 테스트를 동시에 돌리면 실패 | 같은 계정 동시 로그인 제한일 수 있습니다. 순차 실행(`--workers=1`) |
| "그래프 DB에 연결할 수 없어…" | 선택 기능입니다. 쓰려면 `npm run graph:up` |

## 업데이트

- 새 릴리즈가 나오면 1분 안에 사이드패널 이름 옆에 **업데이트 vX.Y.Z**가 뜹니다. 마우스를 올리면 변경 내용이 보이고, 누르면 호스트가 새 버전으로 바뀌어 다시 켜지고 확장도 새로고침됩니다.
- 설치 폴더의 파일을 고쳤으면 업데이트를 멈추고 알립니다. 사용자 데이터는 git 밖(`.env`, `.koa/` 등)에 있어 업데이트에 영향받지 않습니다.
- 릴리즈를 만드는 방법은 [RELEASING.md](RELEASING.md)에 있습니다. 변경 내용은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.
