# 세트 단위 데이터 관리 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 작업 데이터의 기준을 도메인·프로필에서 **세트**(서비스·버전·목적 단위, 대상 사이트 하나)로 바꾸고, 세트별 폴더 하나에 받은 정의·테스트·코드·결과·세션·기록·로그를 모은다.

**Architecture:** 세트 폴더의 경로·읽기·받기는 새 모듈 `sets.mjs`, 세트 테스트 목록 병합은 `testlist.mjs`, 기존 데이터 옮기기는 `migrate-sets.mjs`가 맡는다. 셋 다 데이터 루트를 인자로 받아 임시 폴더에서 `node --test`로 시험한다. 호스트는 지금의 도메인 버킷(`bucket()`) 자리에 세트 경로를 쓰고, 테스트 목록의 원본을 확장 저장소에서 호스트의 `tests.json`으로 옮긴다(패널의 `suite` 모델은 그대로 두고 저장처만 바꾼다). 패널은 프로필 칩·시트를 세트 칩·시트로 바꾼다.

**Tech Stack:** Node ≥20 ESM(`.mjs`), `node:test`(새 의존성 없음), `yaml`, `ws`, Playwright, Chrome MV3 확장(일반 스크립트, 전역 공유).

**Spec:** `docs/superpowers/specs/2026-10-29-sets-data-design.md`

## Global Constraints

- 화면 문구·로그·커밋 메시지는 한국어. 코드 주석 밀도·말투는 주변 코드를 따른다.
- 공개 저장소다. 실제 서비스 이름·주소·내부 IP·결함 번호를 코드·문서·예시·테스트 데이터에 쓰지 않는다. 예시는 `서비스A 2.0 취약점 점검`, `svc-a.example`.
- 대상 사이트는 **세트당 하나**.
- 받은 정의는 읽기 전용. 패널에서 고칠 수 있는 것은 시작 URL·내 계정·역할 범위뿐(이 PC 전용 세트는 예외).
- 세트 정의가 바뀌면 **알림만 주고 사용자가 받기를 누른다**. 자동 덮어쓰기 금지. AI 작업·테스트 실행 중에는 받기·세트 전환 거절.
- 서버로 보내는 형태는 미정. 보내기는 `outbox.mjs` 한 곳에 모으고 지금은 임시 JSON.
- 비밀값(계정 비밀번호, `secrets/`)은 로그·패널 표시·작업 로그에 값이 나가지 않는다. `$KOALA_*` 이름만.
- 새 npm 의존성 금지. 시험은 `node --test`.
- 시험·확인은 임시 데이터 폴더와 다른 포트(`KOALA_PORT=8799`)로 한다. 사용자가 쓰는 호스트(8765)를 끄거나 다시 켜지 않는다.
- 릴리즈(버전·태그·GitHub 릴리즈)는 만들지 않는다. 커밋만. CHANGELOG는 `## 다음 버전 (미배포)`에 3~5줄.
- 임시·반쪽 기능은 `extension/wip.js`의 `WIP`에 등록하고 그 자리에 `wipSign()`을 붙인다. 완성된 항목은 지운다.

## Review Focus

1. 서버의 세트 id에 `/`, 공백, 한글이 들어온 경우 — 폴더 이름은 `safeId`로 바꾸되 세트 id 자체(표시·전송)는 그대로 유지된다. (Task 2 테스트)
2. 세트 정의가 없는 역할·지식·태그 문서를 참조하는 경우 — 받기는 **아무것도 쓰지 않고** 무엇이 없는지 알리며 실패한다. 반쪽 스냅숏을 남기지 않는다. (Task 2 테스트)
3. 옮기기가 중간에 실패하거나 두 번 돌아간 경우 — 다시 돌리면 같은 결과, 원본은 보관 폴더에 남는다. (Task 4 테스트)
4. 같은 도메인의 두 세트를 오가는 경우 — 세션 id, 수행 기록, 테스트 목록, 로그가 섞이지 않는다. (Task 6 통합 확인)
5. 호스트가 꺼진 상태에서 패널을 열거나 세트를 고른 경우 — 패널은 마지막으로 받은 세트 목록을 보여 주고, 테스트 목록이 비었다고 오해하게 하지 않는다("호스트에 연결되면 불러옵니다"). (Task 8 확인)

### Task 2: `sets.mjs` — 세트 경로·목록·받기

**Files:**
- Create: `spike/sets.mjs`, `spike/unit/sets.test.mjs`, `spike/store/sets/example-set.yaml`
- Modify: `spike/sync.mjs` (`KINDS`에 `'set'`)

**Interfaces:**
- Consumes: `DATA`(Task 1), `sync.get(kind, id)`, `sync.catalog()`.
- Produces:
  - `safeId(id: string): string` — `[^\w.-]` → `_`, 빈 값이면 `'default'`.
  - `setPaths(id, root = DATA): { dir, setFile, received, secrets, tests, testsFile, code, results, work, claude, state, recordings, logs, outbox }` — `dir = <root>/sets/<safeId(id)>`, `setFile = dir/set.json`, `testsFile = dir/tests/tests.json`, `code = dir/tests/code`, `claude = dir/work/claude`, `state = dir/work/state.json`, `logs = dir/work/logs`.
  - `readSet(id, root?): SetRecord | null` — `set.json` 내용 `{ id, name, version, source: 'server'|'local', def, refs: { roles?: 'id@vN', knowledge?: ['id@vN'], tags?: ['id@vN'] }, received_at }`.
  - `listSets(root?): Array<{ id, name, version, source, base_url, domain, received: boolean, update: null | { from, to, changed: string[] } }>` — 받은 세트 + 저장소에만 있는 서버 세트(`received:false`).
  - `receiveSet(id, root?): { ok: true, record } | { ok: false, missing: string[] }` — 저장소의 `sets/<id>.yaml`과 참조 문서를 풀어 `received/roles.json`, `received/knowledge/<id>.json`, `received/tags/<id>.json`, 역할 기본 계정은 `secrets/accounts.json`(mode 0600)에 쓴다. 정의의 모르는 키는 `def`에 그대로 둔다. 참조가 하나라도 없으면 아무것도 쓰지 않는다(임시 폴더에 다 쓴 뒤 `renameSync`로 바꿔치기).
  - `checkUpdate(id, root?): null | { from, to, changed: string[] }` — 세트 버전, 참조 문서 버전이 받은 것과 다르면 바뀐 것을 `['세트 v3 → v4', '태그 qa-tags v1 → v2']` 꼴로.
  - `createLocalSet(def, root?): SetRecord` (id는 `local-<safeId(name)>`, 겹치면 `-2`…), `deleteSet(id, root?)` (`source:'local'`만, 아니면 throw).
  - `domainOfSet(record): string` — `def.profile.target.base_url`의 hostname, 없으면 `'default'`.

- [ ] **Step 1: 시험 작성** — 임시 루트에 저장소 흉내(`store/sets/a.yaml`, `store/roles/r.yaml`, `store/tags/t.yaml`, `server-accounts/r.yaml`)를 만들고:

  - 참조 `knowledge: [none]`이면 `{ ok:false, missing:['knowledge/none'] }`이고 `setPaths('a').dir`가 없다(이미 받은 세트였으면 이전 `set.json` 그대로).
  - 저장소의 태그를 v2로 올리면 `checkUpdate('a').changed`에 `'태그 t v1 → v2'`, 받기 전 `readSet('a').refs.tags`는 그대로 `['t@v1']`.
  - `safeId('서비스A/2.0 점검')` === `'___A_2.0___'`, 그 이름으로 받은 세트의 `readSet(...).id`는 원래 문자열 `'서비스A/2.0 점검'`.
  - `deleteSet`을 서버 세트에 부르면 throw.

### Task 4: `migrate-sets.mjs` — 기존 데이터 옮기기
