# 메뉴 경로 지도 — 설계

## 목적

AI가 테스트를 만들 때 **대상 화면까지 어떤 메뉴를 거쳐 가는지**를 매번 다시 뒤지지 않게 한다(1차 목표). 사람도 같은 지도를 펼쳐 본다.
역할별로 보이는지는 2차다. 이번에는 관찰한 역할을 기록만 하고 판정(보임/안 보임)은 하지 않는다.

- 목표: 지나가며 본 메뉴·화면을 세트마다 쌓아, 모든 메뉴의 경로 지도로 자란다.
- 하지 않는 것: 그래프 DB(Docker) 의존.
- 실패로 볼 것: 접었다 편 메뉴나 다른 그룹 클릭이 경로에 섞임, 사이트 정보가 git 에 들어감.

## 용어

- **화면 키** `K(url)` = 호스트 + 경로. 숫자·긴 hex 조각은 `:id`. 해시 라우팅(`#/…`)이면 해시 경로도 붙인다. 쿼리는 버린다.
- **메뉴 영역** = `nav, aside, [role=navigation], [role=menu], [role=menubar], [role=tree], [data-testid^="nav-"]` 안.
- **메뉴 항목** = 메뉴 영역 안의 `a[href]`, `button`, `summary`, `[role=menuitem]`, `[role=treeitem]`, `[aria-expanded]`.
- **목록** = `ul, ol, [role=group], [role=menu], [role=tree]`, 또는 class 에 `items|sub|children|collapse` 가 든 요소.

## 공식

### 1. 메뉴 경로 P(e) — 클릭한 항목 e 의 위치 (화면 구조로)

```
P(e) = [ H(L_k), …, H(L_1), name(e) ]
  L_1 … L_k : e 에서 메뉴 영역 루트까지 올라가며 만나는 '목록' 조상(가까운 것부터)
  H(L)      : L 의 그룹 이름
              = aria-controls 로 L 을 가리키는 요소의 이름
              | L 의 aria-label
              | L 의 앞쪽 형제 중 글자가 있는 첫 요소의 이름
              | 없음(건너뜀)
  name(x)   : aria-label | 자기 글자(하위 목록·아이콘·aria-hidden 제외, 공백 정리, 40자)
  그룹과 항목 이름이 같아도 줄이지 않는다(실제로 '컴플라이언스 › 컴플라이언스' 같은 메뉴가 있다)
  메뉴 영역은 가장 바깥 것을 쓴다(항목마다 data-testid="nav-…" 가 붙은 사이트가 있다)
  본문의 페이지 넘김·이동 경로 표시(pagination·breadcrumb)는 메뉴 영역이 아니다
  이름에서 아이콘·이미지·배지·개수 표시는 뺀다
```

클릭 순서가 아니라 **클릭하는 순간의 구조**로 정한다. 그래서 그룹을 접었다 펴거나 다른 그룹을 먼저 열어 봐도 경로가 흔들리지 않는다.

### 2. 화면에 닿는 길 via(B) — 클릭·이동이 끝났을 때

이동 전 화면 A = K(이전 주소), 이동 후 화면 B = K(새 주소).

| 일어난 일 | 기록 |
|---|---|
| 메뉴 항목 클릭, B ≠ A | `B ← menu P(e)` |
| 메뉴 항목 클릭, B = A | 기록하지 않는다(그룹 펼치기·같은 화면) |
| 메뉴 밖 클릭, B ≠ A | `B ← link(A, name(e))` (상세·하위 화면) |
| goto | `B ← direct` (주소로 바로 들어갈 수 있음) |
| back | 기록하지 않는다 |

같은 길(종류 + 경로, 또는 종류 + 출발 화면 + 이름)은 하나로 합치고 `n`(횟수)·`last`(마지막 시각)·`roles`(역할별 횟수)를 더한다.

### 3. 메뉴에서 본 항목 seen — 화면을 읽을 때(snapshot)

메뉴 영역이 보이면 그 안의 항목마다 `seen[P(e)] = { href, screen: K(href) }`(그룹 머리이면 `group`).
접힌 그룹 안의 숨은 항목도 DOM 에 있으면 함께 읽는다. 그룹 머리 = 하위 목록 바로 앞의 형제(버튼·aria-expanded 가 아니어도).
아직 가지 않은 메뉴도 지도에 '미방문'으로 오른다. DOM 에 없는 하위 메뉴(펼칠 때 그리는 사이트)는 펼쳐서 볼 때 오른다.

### 4. 지도 = 트리

```
메뉴 트리   = 모든 via(menu).P 와 seen 의 경로로 만든 트라이(앞 이름이 같으면 같은 가지)
잎          = 화면 B (방문) | seen.screen (미방문, 메뉴에서만 봄)
하위 화면   = via(link) 의 B 를 출발 화면 A 아래에 단다
주소로만    = via 가 direct 뿐인 화면은 따로 모은다
진척        = 방문한 메뉴 잎 수 / (방문 ∪ 미방문) 메뉴 잎 수
```

한 화면에 메뉴 경로가 여럿이면 모두 남기고, 횟수가 많은 것(같으면 최근 것)을 대표로 보여 준다.

## 저장

세트 폴더(데이터 폴더, git 밖) `sets/<세트>/map/menu.json`. 사람용 `menu-map.md`는 저장할 때마다 다시 만든다.

```json
{ "v": 1,
  "screens": { "<K>": { "title": "", "url": "<마지막 주소>",
    "via": [{ "kind": "menu", "menu": ["운영관리", "사용자 관리"], "n": 3, "last": "…", "roles": { "ADMIN": 3 } },
            { "kind": "link", "from": "<K>", "action": "상세", "n": 1, "last": "…", "roles": {} },
            { "kind": "direct", "n": 2, "last": "…", "roles": {} }] } },
  "seen": { "운영관리›권한": { "menu": ["운영관리", "권한"], "href": "…", "screen": "<K>", "last": "…" } } }
```

## 쓰는 곳

- AI: 지시 수행(둘러보기·작성)과 코드 생성·추가 지시문에 `[메뉴 경로]`를 붙인다(최대 80줄).
  - 화면에 갈 때는 지도의 메뉴 경로를 먼저 쓴다. 지도에 없으면 찾고, 찾은 것은 저절로 지도에 오른다.
  - 코드: BDD 는 메뉴 경로대로 클릭한다(사용자 흐름). TDD 는 시작 화면에 goto 해도 된다. *(내 판단)*
- 사람: 세트 화면(세트 칩) → **메뉴 경로 지도** 칸의 지도 보기(트리·진척·미방문만), 파일 `menu-map.md`.
  지도는 세트(프로필)의 정보라 koala 자체 메뉴(⋯)가 아니라 세트 화면에 둔다.

## 메뉴 전체 돌기 (1차) — AI 없이, 서비스 지식 없이

로그인한 작업 탭에서 시작한다. 조작은 AI 도구와 같은 길(호스트 relay)로 하고 계획 모드로 돈다:
지도 기록·화면 표시·데이터를 바꾸는 버튼 막기를 그대로 쓰고, 수행 기록(테스트)에는 넣지 않는다.

```
items  = 지금 메뉴 항목 목록(공식 3, 숨은 하위 포함)
반복:
  펼쳐 본 적 없고 아는 하위가 없는 그룹 g 가 있으면 → 조상부터 펼치고 g 를 눌러 다시 읽는다 (고정점)
  잎 = 그룹 머리가 아니고 하위가 없는 항목 (펼쳐도 하위가 없는 머리는 주소가 있으면 잎)
  다음 잎 = 아직 끝내지 않은 첫 잎. 없으면 끝
  건너뜀: 이름이 로그아웃·탈퇴·삭제·초기화 등 / 새 탭·다른 사이트 / 파일 내려받기
  조상 그룹 중 하위가 모두 숨은 것을 차례로 눌러 펼친 뒤, 잎을 메뉴 경로로 찾아 누른다(locator { menu: P })
  다시 읽어 비밀번호 입력란이 보이면 로그인 풀림 → 멈춤
```

- 이어하기: 끝낸 잎 경로를 `map/crawl.json` 에 남기고, 끝나지 않은 같은 종류를 다시 누르면 거기서 이어간다.
- 결과: 방문·실패(이유)·건너뜀(이유)과, 돌리는 동안 앱이 보낸 쓰기 요청(GET 아닌 것)을 모아 보고한다.

## 목록 상세 돌기 (2차)

1차와 같이 돌되 잎 화면마다 목록(표)의 첫 데이터 행을 눌러 본다(locator { row: true }).

```
누를 곳 = 표마다 첫 데이터 행의 링크 | 버튼·입력·체크박스가 없는 첫 칸 (한 칸짜리 '데이터 없음' 행은 건너뜀)
누름 실패 → 1초 뒤 한 번 더(늦게 그려지는 목록). 그래도 없으면 '빈 목록이거나 누를 칸이 없음'
누른 뒤 변화가 없으면 1초 뒤 한 번 더 본다
  주소가 바뀜        → 상세 화면(지도: 목록 화면 아래 '목록 행' 링크) → 뒤로 가기
  대화상자(role=dialog) → 상세 대화상자(지도: '목록 화면 ⧉ 목록 행') → Escape
  화면 요소 수가 20% 넘게 바뀜 → 같은 화면 안 상세(옆 패널·행 펼침)
  그 밖               → 상세 없음
```

## 검토 (목업 withVTM, ADMIN, 2026-10-30)

| | AI 수행 | 메뉴 전체 돌기 | 목록 상세 돌기 |
|---|---|---|---|
| 방문 | 51/51 | 51/51 · 실패 0 | 51/51 |
| 시간·비용 | 약 4분 · 약 $0.99 | 약 1분 · 0 | 약 2분 · 0 |
| 상세 | - | - | 새 화면 23 · 대화상자 5 · 없음 14 · 목록 없음 9 |

- 1차는 정적으로 읽은 44개가 아니라 펼쳐야 그려지는 그룹까지 51개를 모두 찾았다(고정점이 필요한 근거).
- 2차 '없음' 14 중 8은 누를 행을 찾지 못함, 6은 행을 눌러도 바뀌지 않음.
  확인한 것은 둘: 결재대기는 작업 탭에서 목록이 비어 있었고(NO DATA) 같은 시각 새 브라우저에서는 행이 있었다(탭에 저장된 검색 조건 등 상태 차이로 추정, 확인 안 함).
  보고서는 새 브라우저에서도 행을 눌러 바뀌는 것이 없었다. 나머지는 확인하지 않았다.
- 데이터를 지우거나 고치는 요청(PUT·DELETE)은 없었다. 다만 **화면을 보기만 해도 앱이 보내는 POST** 가 있다:
  배지 읽음 처리(`badges/…/resolve`·`…/view`), 파일 파싱 프로필 상세의 미리보기·매핑 검사. 상세 돌기는 '읽음' 상태를 바꾼다.
- 한계: 데이터가 있어야 열리는 상세, 검색해야 나오는 목록, 행마다 다른 상세(첫 행 표본만), 클릭 대신 더블클릭·hover 로 여는 상세는 못 찾는다.

## 구현 위치

- `extension/menu.js`: 페이지에 넣는 도우미(`path`·`items`·`findAll`·`rowTargets`). overlay.js 처럼 필요할 때 주입.
- `extension/sidepanel.js`: click·goto·back·snapshot 결과에 `navItems`, click 결과에 `menu`·`label`, locator `{ menu }`·`{ row }`.
- `spike/menumap.mjs`: 공식 2~4(기록·합치기·트리·AI용 요약·사람용 md). 화면 키 `K`.
- `spike/crawler.mjs`: 메뉴 전체 돌기·목록 상세 돌기(조작은 주입받은 act·read 로, 가짜 사이트로 단위 테스트).
- `spike/host.mjs`: relay 결과로 기록, `navItems` 는 AI에게 넘기지 않음, 지시문에 요약, 크롤 작업·이어하기·쓰기 요청 모으기.
- `extension/sets.js`·`menumap-view.js`: 세트 화면의 메뉴 경로 지도 칸, 지도 보기.

## 나중

- 쓰기 요청 막기 선택(GET 만 통과): 목록 조회가 POST 인 사이트는 빈 화면이 되므로 선택으로 둔다.
- 역할별로 돌려 보임 판정(seen·via 의 roles 로 역할 × 메뉴 표), 실행 간 비교(새로 생긴·사라진 메뉴).
- 상세 안의 탭·링크로 더 들어가기(깊이·건수 예산), 행 표본 늘리기.
- 같은 주소에서 내용만 바뀌는 화면을 '보기'로 구분.
