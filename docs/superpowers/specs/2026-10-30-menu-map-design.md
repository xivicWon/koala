# 메뉴 경로 지도 — 설계

## 목적

AI가 테스트를 만들 때 **대상 화면까지 어떤 메뉴를 거쳐 가는지**를 매번 다시 뒤지지 않게 한다(1차 목표). 사람도 같은 지도를 펼쳐 본다.
역할별로 보이는지는 2차다. 이번에는 관찰한 역할을 기록만 하고 판정(보임/안 보임)은 하지 않는다.

- 목표: 지나가며 본 메뉴·화면을 세트마다 쌓아, 모든 메뉴의 경로 지도로 자란다.
- 하지 않는 것: 메뉴를 전부 펼쳐 도는 자동 순회(나중), 패널 화면(나중), 그래프 DB(Docker) 의존.
- 실패로 볼 것: 접었다 편 메뉴나 다른 그룹 클릭이 경로에 섞임, 사이트 정보가 git 에 들어감.

## 용어

- **화면 키** `K(url)` = 호스트 + 경로. 숫자·긴 hex 조각은 `:id`. 해시 라우팅(`#/…`)이면 해시 경로도 붙인다. 쿼리는 버린다.
- **메뉴 영역** = `nav, aside, [role=navigation], [role=menu], [role=menubar], [role=tree], [data-testid^="nav-"]` 안.
- **메뉴 항목** = 메뉴 영역 안의 `a[href]`, `button`, `summary`, `[role=menuitem]`, `[role=treeitem]`, `[aria-expanded]`.
- **목록** = `ul, ol, [role=group], [role=menu], [role=tree]`, 또는 class 에 `items|sub|children|collapse` 가 든 요소.

## 공식

### 1. 메뉴 경로 P(e) — 클릭한 항목 e 의 위치 (화면 구조로)

```
P(e) = [ H(L_k), …, H(L_1), name(e) ]
  L_1 … L_k : e 에서 메뉴 영역 루트까지 올라가며 만나는 '목록' 조상(가까운 것부터)
  H(L)      : L 의 그룹 이름
              = aria-controls 로 L 을 가리키는 요소의 이름
              | L 의 aria-label
              | L 의 앞쪽 형제 중 글자가 있는 첫 요소의 이름
              | 없음(건너뜀)
  name(x)   : aria-label | 자기 글자(하위 목록·아이콘·aria-hidden 제외, 공백 정리, 40자)
  같은 이름이 연달아 나오면 하나로 줄인다
```

클릭 순서가 아니라 **클릭하는 순간의 구조**로 정한다. 그래서 그룹을 접었다 펴거나 다른 그룹을 먼저 열어 봐도 경로가 흔들리지 않는다.

### 2. 화면에 닿는 길 via(B) — 클릭·이동이 끝났을 때

이동 전 화면 A = K(이전 주소), 이동 후 화면 B = K(새 주소).

| 일어난 일 | 기록 |
|---|---|
| 메뉴 항목 클릭, B ≠ A | `B ← menu P(e)` |
| 메뉴 항목 클릭, B = A | 기록하지 않는다(그룹 펼치기·같은 화면) |
| 메뉴 밖 클릭, B ≠ A | `B ← link(A, name(e))` (상세·하위 화면) |
| goto | `B ← direct` (주소로 바로 들어갈 수 있음) |
| back | 기록하지 않는다 |

같은 길(종류 + 경로, 또는 종류 + 출발 화면 + 이름)은 하나로 합치고 `n`(횟수)·`last`(마지막 시각)·`roles`(역할별 횟수)를 더한다.

### 3. 메뉴에서 본 항목 seen — 화면을 읽을 때(snapshot)

보이는 메뉴 항목마다 `seen[P(e)] = { href, screen: K(href) }`(펼친 그룹 머리이면 `group`).
아직 가지 않은 메뉴도 지도에 '미방문'으로 오른다. 접힌 그룹 안은 펼쳐서 볼 때 오른다.

### 4. 지도 = 트리

```
메뉴 트리   = 모든 via(menu).P 와 seen 의 경로로 만든 트라이(앞 이름이 같으면 같은 가지)
잎          = 화면 B (방문) | seen.screen (미방문, 메뉴에서만 봄)
하위 화면   = via(link) 의 B 를 출발 화면 A 아래에 단다
주소로만    = via 가 direct 뿐인 화면은 따로 모은다
진척        = 방문한 메뉴 잎 수 / (방문 ∪ 미방문) 메뉴 잎 수
```

한 화면에 메뉴 경로가 여럿이면 모두 남기고, 횟수가 많은 것(같으면 최근 것)을 대표로 보여 준다.

## 저장

세트 폴더(데이터 폴더, git 밖) `sets/<세트>/map/menu.json`. 사람용 `menu-map.md`는 저장할 때마다 다시 만든다.

```json
{ "v": 1,
  "screens": { "<K>": { "title": "", "url": "<마지막 주소>",
    "via": [{ "kind": "menu", "menu": ["운영관리", "사용자 관리"], "n": 3, "last": "…", "roles": { "ADMIN": 3 } },
            { "kind": "link", "from": "<K>", "action": "상세", "n": 1, "last": "…", "roles": {} },
            { "kind": "direct", "n": 2, "last": "…", "roles": {} }] } },
  "seen": { "운영관리›권한": { "menu": ["운영관리", "권한"], "href": "…", "screen": "<K>", "last": "…" } } }
```

## 쓰는 곳

- AI: 지시 수행(둘러보기·작성)과 코드 생성·추가 지시문에 `[메뉴 경로]`를 붙인다(최대 80줄).
  - 화면에 갈 때는 지도의 메뉴 경로를 먼저 쓴다. 지도에 없으면 찾고, 찾은 것은 저절로 지도에 오른다.
  - 코드: BDD 는 메뉴 경로대로 클릭한다(사용자 흐름). TDD 는 시작 화면에 goto 해도 된다. *(내 판단)*
- 사람: `menu-map.md`(트리·하위 화면·주소로만·진척).

## 구현 위치

- `extension/menu.js`: 페이지에 넣는 도우미(`window.__koalaMenu.path(el)`·`items()`). overlay.js 처럼 필요할 때 주입.
- `extension/sidepanel.js`: click 결과에 `menu`(P(e), 메뉴 항목일 때)·`label`(name(e)), snapshot 결과에 `navItems`.
- `spike/menumap.mjs`: 공식 2~4(기록·합치기·트리·AI용 요약·사람용 md). 화면 키 `K`.
- `spike/host.mjs`: relay 결과로 기록, `navItems` 는 AI에게 넘기지 않음, 지시문에 요약.

## 나중

- 메뉴를 펼쳐 모든 잎을 도는 순회 작업(진척 100% 로).
- 역할별 보임 판정(seen·via 의 roles 로 역할 × 메뉴 표).
- 같은 주소에서 내용만 바뀌는 화면(탭·SPA 내부 전환)을 '보기'로 구분.
- 패널에서 지도 보기.
