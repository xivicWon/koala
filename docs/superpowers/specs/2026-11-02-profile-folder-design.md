# 프로필 = 폴더 — 설계

## 목적

프로필 정의를 사용자가 직접 바꿀 수 있게 하고, "지식·태그와 버전·규칙"처럼 출처가 흐린 개념을 없앤다.
Claude Code 가 사용자 레벨과 프로젝트 레벨을 읽듯이 koala 도 **폴더의 파일을 다 읽는다**. 프로필은 **`~/koala-profiles/` 아래 폴더 하나**이고, 사용자가 정하는 것은 **폴더 이름**뿐이다.

- 실패로 볼 것: 출처를 알 수 없는 설정이 남음, 계정 값이 폴더에 들어감, 기존 프로필의 테스트·기록이 끊김, koala 업데이트가 사용자 파일을 덮어씀.

## 세 층

| 층 | 위치 | 누가 고치나 |
|---|---|---|
| koala 기본 | koala 설치 폴더 `spike/prompts/` (공통 QA 원칙 포함) | koala 만. 업데이트로 바뀌므로 사용자·AI 는 고치지 않는다 |
| 사용자 레벨 | `~/.koala/` 안의 파일 전부(텍스트) | 사용자 |
| 프로젝트 레벨(= 프로필) | `~/koala-profiles/<이름>/` 안의 파일 전부(텍스트) | 사용자, 그리고 AI(새 파일 추가만) |

- 폴더 안의 텍스트 파일(`.md .txt .yaml .yml .json`)을 하위 폴더까지 모두 읽는다. 어떤 파일을 읽는지 적어 두지 않는다.
  빼는 것: 숨김 폴더(`.koala/` 만 읽음. 작업 데이터 `.koala-work/`·`.git/` 등은 안 읽음), `node_modules`, 200KB 넘는 파일, 그 밖의 확장자.
  `~/.koala/` 에서는 koala 가 쓰는 파일(로그·키·실행기)을 뺀다.
- 바꾸고 싶은 것은 **기본 파일을 고치지 말고 새 파일을 추가**한다. 뒤에 읽히는 층(프로젝트 > 사용자 > koala 기본)이 우선한다.
- AI 는 프로필 폴더의 `.koala/rules/` 에 **자기 파일만** 쓴다(`save_rule`). koala 기본 파일·사용자가 만든 파일은 고치지 않는다.

## 값을 읽는 파일: `<프로필 폴더>/.koala/settings.json`

대상 주소처럼 koala 가 코드로 읽는 값만 여기 둔다. 패널에서 따로 입력받지 않고, 처음 등록할 때 틀을 넣어 준다.

```json
{
  "base_url": "http://192.168.140.23",
  "start_path": "/login",
  "deploy_url": "",
  "roles": [{ "key": "ADMIN", "label": "관리자", "desc": "서비스 관리자" }],
  "default_role": "ADMIN",
  "tags": { "groups": [] },
  "cleanup": []
}
```

- 이름은 폴더 이름(`settings.json` 에 `name` 이 있으면 그것).
- 계정 값은 넣지 않는다. 계정은 패널의 '내 설정'(이 확장)과 `.koala-work/secrets/`(옮긴 프로필의 기본 계정, 본인만 읽기).
- `receive_url`(받는 서버)은 실제 서버가 생기면 쓴다. 지금은 공사 중.

## 처음 등록할 때 넣어 주는 기본 파일

폴더에 `KOALA.md`·`.koala/settings.json`·`.gitignore` 가 없을 때만 만든다(있으면 건드리지 않는다).
- `KOALA.md`: 이 사이트에 대해 AI 에게 줄 글을 쓰는 곳. 맨 위에 "이 폴더의 파일은 모두 읽힌다, 주제별로 파일을 추가해도 된다" 안내.
- `.koala/settings.json`: 위 틀(대상 주소만 비어 있음).
- `.gitignore`: `.koala-work/` (폴더를 git 으로 공유해도 기록·계정이 올라가지 않게).
- `~/.koala/KOALA.md` 가 없으면 사용자 레벨 안내만 든 빈 틀을 만든다.

## AI 에게 전달

- 작업 폴더의 `CLAUDE.md` 는 사본을 만들지 않고 절대 경로 `@` import 만 둔다:
  koala 기본(`spike/prompts/qa-common.md`) → 사용자 레벨 파일 → 프로젝트 레벨 파일(`.koala/rules/`·`settings.json` 제외).
  파일 목록이 바뀌면 다음 지시는 새 대화로 시작한다. 내용만 바뀐 것은 새 대화에서 읽힌다.
- 규칙(`~/.koala/rules/`, `<폴더>/.koala/rules/`)은 대화가 끊기지 않게 지금처럼 호스트가 지시할 때마다 붙인다.

## 프로필 목록과 작업 데이터

- 따로 등록하는 목록이 없다. **`~/koala-profiles/` 의 하위 폴더가 곧 프로필**이다(숨김 폴더 제외). 폴더 이름이 프로필 id.
  위치는 바꾸지 않는다(시험용으로만 `KOALA_PROFILES` 로 바꿈).
- **작업 데이터도 프로필 폴더 안** `.koala-work/` 에 둔다: `tests/`(목록·코드·결과), `work/`(수행 기록·세션·로그·Claude 작업 폴더),
  `map/`, `outbox/`, `secrets/`(0600). 숨김 폴더라 AI 에게 읽히지 않는다. 옮기기·백업·지우기가 폴더 하나로 끝난다.
- koala 데이터 폴더(`spike/.koa/`)에는 프로필과 상관없는 것만 남는다(호스트 토큰, 서버 흉내 저장소).
- 패널: 목록(이름·대상 도메인), **새 프로필**(이름 하나 → 폴더와 기본 파일 틀을 만듦), **폴더 열기**, '읽는 파일'(층별 목록),
  **지우기**(폴더째 `~/koala-profiles/.deleted/<이름>-<시각>/` 로 옮김, 되살릴 수 있음), 내 설정(계정·역할 범위).
- 폴더를 직접 만들어 넣어도 다음 목록 갱신 때 프로필로 보인다(기본 파일이 없으면 그때 틀을 넣는다).

## 기존 프로필 옮기기 (호스트가 켜질 때 한 번)

`sets/<id>/set.json` 이 있고 `~/koala-profiles/<id>/` 가 없는 프로필마다 그 폴더를 만든다(이름이 같으므로 작업 데이터와 그대로 이어진다).
- `KOALA.md`: 사이트 운영 팁(prompt)과 받은 지식 중 공통 QA 원칙이 아닌 것의 본문.
- `.koala/settings.json`: 대상 주소·시작 경로(시작 URL 이나 로그인 경로)·보내는 서버·역할·기본 역할·태그·정리 규칙·claude.
- `.koala/rules/` ← `sets/<id>/rules/*.md`, `.koala-work/` ← `sets/<id>/` 의 tests·work·map·outbox·secrets (복사). 원본 `sets/<id>/` 는 지우지 않고 그대로 둔다.
- 패널 '내 설정'의 시작 URL 은 그대로 쓴다(있으면 settings 보다 우선).
- 받지 않은 저장소 프로필(서버 흉내)은 목록에서 빠진다.
